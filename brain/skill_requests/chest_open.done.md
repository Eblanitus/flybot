# chest_open: готово
Версия: chest_open_v5 (основа — chest_open «была текущей на 22.10», 24/24; код скопирован, после подготовки добавлено чтение содержимого; base-файл chest_open.js и старые версии не тронуты)
Запуск: curl.exe -s "http://127.0.0.1:3200/go?name=chest_open_v5&x=-391&y=67&z=34"  |  «есть ли X?» — "http://127.0.0.1:3200/go?name=chest_open_v5&x=-391&y=67&z=34&item=bread"
Params: x/y/z — координаты сундука (не заданы — найдёт видимый глазами или тот, что помнит тело); item — имя предмета (точное: bread, charcoal, cobblestone): ответ have (0 — нет), БЕЗ взятия; dig_above — 0 не копать / 1 (по умолчанию) выкопать мягкий блок над сундуком / 2 любой (кроме контейнера); hand — auto (по умолчанию, убрать блок из руки) / toss (выбросить блок) / skip; walk_sec — секунд на подход, по умолчанию 20; open_sec — сколько ждать окно, по умолчанию 5 (2–20)
Что делает: находит сундук, подходит, убирает помехи открытия (блок над сундуком, блок в руке), затем открывает окно навыком тела chest_take БЕЗ item — тело строит {имя: количество} и закрывает окно, НИЧЕГО не беря (took 0, дроп сундука не тронут). Успех: {ok:true, chest:[x,y,z], content:{предмет:шт}, took:0, types, total, fly, faces, above, held, note}; с item — ещё have (0 = «нет»). Отказ: {ok:false, error:'…'} с chest/fly/blocker/faces/above/held — «сундук не виден», «над сундуком блок», «сбоку занято», «в руке блок», «окно не открылось за N с»; сундук ПУСТОЙ — это успех (content {}) и note «внутри пусто», не провал. Каждый прогон пишет в журнал (:3200/log) «взято 0 (должно быть 0), внутри … видов: …».
Ограничения: не встаёт дальше 25 м — сначала подведи муху (go_safe), потом зови; item — точное имя предмета, как в содержимом; открывает chest/trapped_chest/barrel (то же, что chest_take тела) — печь/бункер не читает; ничего не берёт: если нужно взять — это chest_take, теперь МОЖНО сначала посмотреть chest_open_v5.
