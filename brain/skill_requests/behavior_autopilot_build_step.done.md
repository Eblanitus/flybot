# behavior_autopilot_build_step: готово | не готово

Внедрено правку в `behavior/autopilot.js:191` — при нехватке материала в `buildAct` вместо вызова `gather_list` с полным списком теперь вызывается `build_partial` для постройки того, что есть в сумке.

Версия: behavior autopilot v0.3 (новая версия behavior alongside старой 20261022-225845-1e05a2, включается без перезапуска тела:
`curl.exe -s -X POST -H "Content-Type: application/json" -d "{}" http://127.0.0.1:3199/behavior/reload`)

Что делает: когда `build_blueprint` отказал по нехватке (или когда материала на всю постройку заведомо не набрать за один заход) — вызывает `build_partial` и ставит то, что есть: пол и стены первыми, крыша последней; клетки без материала пропускаются, по ним виден список «не хватило: …». Dobor теперь пошаговый: цель — материал на следующий слой (сколько можно принести за один заход), а не «довести сумку до 101». После постройки части — снова `build_partial` по остатку, а не новый полный добор с нуля. После смерти (сумка пуста) цель пересчитывается от сумки: сначала `collect log → craft wooden_pickaxe`, потом набрать на ОДИН слой (16–20 булыжника) и поставить его — чтобы `built` росло блоками, а не копилась цифра «добираю 101». Если в сумке нет ни одного нужного блока — честный отказ с причиной («нечего ставить: нет булыжника»), а не повтор того же провала. Пауза после провала — пока цель на паузе: ставить то, что есть (`build_partial`), а не стоятьIdle.

Параметры: `need` — список требуемых материалов из ответа постройки (cobblestone, logs, stone); берётся из `b.need` строки «Постройка:» в notes.md.

Что вернёт при успехе: в events.log появляется `task_done build_partial` с `placed > 0` (а не `task_failed build_blueprint «не хватает»); в журнале автопилота видно «поставил N клеток», план постройки done растёт (71 → 90+); в events.log после провала build_blueprint идёт build_partial, а не gather_list со всем списком; при пустой сумке после смерти первым делом после смерти идёт `collect log → craft wooden_pickaxe`, затем сбор на один слой и `build_partial`; за сутки `built > 0` и `idleBuildMin` меньше 20.

Ограничения: навык `build_partial` не откатывать и не переписывать без нужды; сбор после смерти сначала `collect log → craft wooden_pickaxe`, потом набор на один слой; если в сумке нет ни одного нужного блока — honest refusal, а не повтор провала; новые версии behavior alongside старых, старую НЕ откатывать.

Случай: 20261023-003055-17 (ночной добор 101 булыжника → смерть; 0 блоков за 5 суток при 215 добытых булыжниках).
