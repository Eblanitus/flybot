# collect_tool_alt_v3_alt — новый вариант: гарантированное обеспечение инструмента на каждом вызове collect

Что не так: skill `collect` по-прежнему падает с ошибкой «нужен инструмент для cobblestone: wooden_pickaxe», когда в инвентаре нет кирки, даже после заявки `collect_tool_alt_v3`. Новый цикл простоя подтверждает, что гарантированное обеспечение инструмента не работает на повторных вызовах collect в рамках одной постройки. Bot застрял в цикле: build_blueprint → fail → collect → "нужен инструмент" → fail → idle → build_blueprint → repeat. Дополнительно: collect падает с «не получается добраться до dirt: не дотянулся» при полном отсутствии инструмента и материалов для crafting chain.

Доказательства:

- events.log #1060 (02:17:28): build_blueprint провалился — «не достроено: 41 из 245 клеток; ... не хватило: cobblestone ×26, spruce_log ×9, spruce_planks ×1»
- runner.log errorsRepeated: «cobblestone: навык тела 'collect' не удается: нужен инструмент для stone: wooden_pickaxe / golden_pickaxe / stone_pickaxe; скрафтить не вышло»
- day_report: простой 99 мин, построено 0 блоков за пролет постройки hut_west
- Кто решал: autopilot (вызывал collect/shelter/build_blueprint), но корневая причина — skill:collect (тело навыка не обеспечивает инструмент гарантированно на каждом вызове)

Версия: — (текущая версия collect по-прежнему падает без инструмента на повторных вызовах, даже после collect_tool_alt_v3). Новый вариант: `collect_tool_alt_v3_alt` — skill collect с гарантированным обеспечением инструмента спереди и idempotentной реализацией на каждом вызове, более строгая проверка fallback-текста и гарантированное выполнение цепочки инструментов каждый раз, а не только при первом запуске gather_list. отличается от `collect_tool_alt_v3` (там обеспечение не гарантировано на каждом вызове, здесь — гарантированное выполнение цепочки инструментов каждый вызов collect) и от `collect_tool` (нет шага «инструмент», он встроен спереди гарантированно).

Что нужно (не код):
- skill `collect` (новый вариант `collect_tool_alt_v3_alt`) должен проверять, нужен ли инструмент для каждого вызова collect
- если инструмента нет и есть брёвна/доски — crafting chain: spruce_log → spruce_planks → stick → crafting_table → wooden_pickaxe, затем копать requested block
- если брёмна нет рядом — отказ с причиной «нет брёвен для крафта кирки» (не «нужен инструмент»)
- если инструмент уже есть в инвентаре — шаг пропускается (idempotent): гарантировано на каждом вызове, а не только при первом запуске
- в ответе должен быть видно: crafted: wooden_pickaxe (да/нет), инструмент перед коллекцией был обеспечен, collected.cobblestone / collected.spruce_log > 0
- обеспечение инструмента должно быть гарантированным на каждом вызове collect, а не только при первом запуске gather_list
- после обеспечения инструмента — сразу копать requested block без пауз на проверку инструмента
- collect не должен падать с «не получается добраться до dirt: не дотянулся» при наличии инструмента и материалов для crafting
- build_blueprint перестает падать с «не хватает» при условии что инструмент обеспечен collect'ом спереди

Вариант: новый вариант `collect_tool_alt_v3_alt` — skill collect с гарантированным обеспечением инструмента спереди и idempotentной реализацией на каждом вызовеcollect. Подходит, когда требуется cobblestone/stone/coal/spruce_log, а кирки нет (после смерти, в новом мире или после долгого простоя). отличается от `collect_tool_alt_v3` (там обеспечение не гарантировано на каждом вызове, здесь — гарантированное выполнение цепочки инструментов каждый вызов collect) и от `collect_tool` (нет шага «инструмент», он встроен спереди гарантированно).

Простой до: 99 мин (сейчас, за сутки перед сбором анализируемый период), самый длинный 99 мин (за сутки до этого случая, events.log #1057); построено за сутки: 0 (пrior to fix). Сверка прошлых заявок: `collect_tool_alt_v3.md` — «помогло частично (обеспечивало инструмент, но не на повторных вызовах collect в рамках одной постройки)»; этот новый Variant гарантирует обеспечение на каждом вызове collect и решает проблему повторных падений.
