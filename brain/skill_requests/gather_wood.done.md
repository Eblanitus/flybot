# gather_wood: готово

Запуск: `curl.exe -s "http://127.0.0.1:3200/go?name=gather_wood&count=24&x=-379&y=66&z=85"`

Params:
- `count` — сколько брёвен, по умолчанию 8
- `x`, `y`, `z` — точка леса, по умолчанию -472 / 69 / 37
- `step` — длина участка пути, м (4..16), по умолчанию 10
- `radius` — радиус сбора вокруг текущей точки, м (8..24), по умолчанию 12 (было 48)
- `min_hp` — минимальный HP для похода, по умолчанию 3 (то есть при HP ≤ 2 отказ)
- `min_food` — минимальная еда для регена, по умолчанию 18
- `wait_regen` — ждать регена до N с при низком HP, по умолчанию 45 (0 — не ждать)
- `arrive` — лес считается достигнутым в N м, по умолчанию 6
- `max_sec` — потолок времени навыка, по умолчанию 240

Что делает:
1. Снимок до старта: при HP ≤ 2 (или еды < 18 и дорога > 60 м, когда регена нет) возвращает `{ok:false, error:'мало HP/нет еды — сначала еда'}` и не выходит; если еда есть и реген возможен — ждёт регена до `wait_regen` с.
2. Идёт к лесу участками по `step` м. Перед каждым участком: `survey` коридора (поверхность, обрывы, лава) + «обрыв» из `eyes.hazards` снимка. Перепад вниз больше безопасного (урон падения = перепад − 3, запас 2 HP) не перешагивается: уходит вбок (обход ±8/±16 м) или отказываемся с причиной. Длинного `goto` больше нет.
3. Собирает рядом с точкой леса: `collect` с малым радиусом, к цели подходит короткими шагами по 6 м (точки вокруг точки леса), максимум один короткий `explore` (16 м) при HP ≥ 8.
4. Смерть (по тексту ошибки или по счётчику `stats.deaths`) или падение HP — сразу стоп с этой причиной, тот же путь не повторяется. Лог: точка, расстояние, перепад, HP, число брёвен.

Возвращает при успехе `{ok:true, collected, gained, at, calls, sec}`; при провале `{ok:false, error:<причина>}` — «мало HP/нет еды — сначала еда», «не пройти к лесу …: обрыв N м …», «смерть …», «в лесу брёвен мало (0/8) — смени точку леса».

Ограничения:
- Навык сам не ест и не ждёт регена, если еды нет: при низком HP он честно отказывается идти — сначала еда (навык `eat`), потом повтор.
- `survey` видит только то, что видно: если под ногами/за краем поверхность не видна (глубокий каньон), участок помечается «под ногами не видно» и не проходится — это осознанно строго, обход может не найтись.
- Обрывы определяются по `survey` и `eyes.hazards`; тело само по себе урон от падения не учитывает, полную гарантию дать нельзя.
- Внутри `collect` тело само ходит к известному месту (`worldmem`), если брёвен не видно — это его собственный длинный переход, навык за него не отвечает.
- Навык был авто-выключен за 3 провала подряд — проверен (`/check` ok) и включён обратно (`/enable`), `consecutiveFails` сброшен.

Попутно исправлена вторая причина вечных «брёвен 0/N»: старый код считал `api.count('log')`, а в инвентаре брёвна называются `spruce_log`/`oak_log` — счёт всегда давал 0. Теперь `api.count(/_log$/)`.
