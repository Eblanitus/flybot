# gather_list_alt_resources — от учителя

Что не так: autopilot циклически пытался build_blueprint hut_west, не проверяя достаточности ресурсов, — idle вырос с 20 до 136 мин за день, построено 0 блоков. gather_list собирал cobblestone:25, spruce_fence:2, но этого мало для Blueprint'a needing 101 cobblestone + 5 spruce_fence. Навык имел проблемы с синонимами (stone → cobblestone) и не проверял недостижимость ДО сбора.

Доказательства:
- events.log #1132 — "добираю для постройки hut_west: cobblestone:25, spruce_fence:2 (простой 125 мин)" — gather_list дал мало ресурсов
- events.log #1140-#1211 — repeated build_blueprint failures: "не хватает: cobblestone ×17/25/33, spruce_fence ×2" без проверки можно ли собрать достаточно за 합리ное время
- runner.log runs 16-17 — gather_list failed: "навык тела collect не удался: нужен инструмент для cobblestone: wooden_pickaxe / golden_pickaxe / stone_pickaxe" (synonym issue)
- day_report день 9: "построено 0 блоков, простой 20 мин (самый длинный 136 мин), warn: стройка за день не сдвинулась: 0 блоков построено"
- runner.log run 25 — gather_list ok с cobblestone:25, spruce_fence:2 (максимально за один прогон)

Кто решал: skill:gather_list (код) и autopilot (поведение) — код собирал ресурсы с проблемами имен и количеств, поведение не проверяло достаточно ли перед build.

Версия: — (текущая версия gather_list имеет известные недостатки по item synonyms и amount reliability)

Что нужно (правка существующего навыка, новый вариант):
- Автопилот должен проверять уровень ресурсов ПЕРЕД запуском build_blueprint: если не хватает ключевых материалов — сначала собрать (gather_list), а не пытаться строить и падать с ошибкой
- gather_list должен писать настоящие имена инвентаря в `missing`/`collected`/`plan` с переименованиями (stone→cobblestone), чтобы следующий вызов был рабочим сразу
- gather_list должен проверять недостижимость предметов ДО сбора: если в списке есть предмет, которого нет в инвентаре и нет в рецептах/срёве — сразу вернуть `{ok:false, error:"не знаю, как получить X xN (похоже на cobblestone)", missing, hint}` без начала collect
- gather_list должен гарантировать минимальное требуемое количество для известных проектов: например, при сборке под hut_west — собирать минимум cobblestone:50 за один прогон или писать plan с явным недогather
- В error gather_list указывать конкретное рекомендуемое имя (например: «не добрал: cobblestone ×25 (советуй: cobblestone, нужна кирка wooden_pickaxe)»)

Вариант: «исправление текущей версии» — добавить проверку ресурсов перед build_blueprompt и улучшить надежность количеств в gather_list; или «новый вариант: gather_list_resources_adequate» — отдельный вариант навыка, который всегда гарантирует минимум N предметов дляKnown проектов или отказывается с четкой причиной.

Как проверить: 
- Запуск build_blueprint hut_west до сбора ресурсов должен давать ошибку «недостаточно ресурсов, собирай сначала» вместо провала mid-build
- Запуск gather_list items="cobblestone:50,spruce_fence:5" должен возвращать ok с минимум этих количеств или ошибку с подсказкой
- В runner.log не должно остаться провалов с текстом «не знаю, как получить stone» или «не хватает: ...» при повторных попытках
- Длина простоя за сутки должна сократиться с 136 мин до 합리льного (например, <30 мин) при правильной проверке ресурсов
