# collect_tool_alt_v2 — от учителя

Что не так: skill `collect` по-прежнему падает с ошибкой «нужен инструмент для cobblestone: wooden_pickaxe», когда в инвентаре нет кирки, даже если уже существовала заявка `collect_tool`. Новый цикл простоя подтверждает, что старый вариант не покрывает случай, когда инструмента нет совсем (после смерти, новый мир, долгий простой). Bot застрял в цикле: build_blueprint → fail → gather_list → collect → "нужен инструмент" → fail → idle.

Доказательства:
- events.log #1141, #1157, #1164, #1177, #1209 (15:05:52–15:13:14): build_blueprint провалился 5 раз подряд по одной и той же причине нехватки cobblestone/spruce_fence
- runner.log #16, #17, #28, #29 (раньше), а также текущий цикл: collect падает «нужен инструмент для cobblestone: wooden_pickaxe» даже когда заявка collect_tool supposed to mitigate
- runner.log #3506/#3507: gather_list_alt_tool_v1 TypeError: targets is not iterable (попытка починить цепочку инструментов另一种 way)
- brain/learned/collect.js: тело skill collect не содержит логики обеспечения инструмента перед добычей (файл не изменен за сутки)
- Сравнение с collect_tool.md: он обещал обеспечение инструмента «спереди», но на практике skill по-прежнему отказывается без инструмента — значит шаг не был надежно внедрен или есть边缘-случай, когда inventory пуст полностью

Кто decided: autopilot (вызывал build_blueprint), но корневая причина — skill:collect (тело навыка не обеспечивает инструмент на каждом вызове)

Версия: — (текущая версия collect по-прежнему падает без инструмента). Новый вариант: `collect_tool_alt_v2` — skill collect с надежным обеспечением инструмента спереди, который (1) проверяет, нужен ли инструмент для блока, (2) если нет — гарантирует его создание из доступных материалов (берёнов/досок/палок), (3) если материалов недостаточно — честный отказ с причиной «нет брёвен для крафта кирки», а не «нужен инструмент», (4) после обеспечения инструмента сразу копает requested block. отличается от collect_tool тем, что имеет stricter проверку и fallback-текст, а отличается от gather_list_alt_tool_v1 тем, что не падает с TypeError — здесь реальная цепочка инструментов.

Что нужно (не код):
- skill `collect` (новый вариант `collect_tool_alt_v2`) должен проверять, нужен ли инструмент для каждого блока в плане сбора
- если инструмента нет и есть брёвна/доски — crafting chain: spruce_log → spruce_planks → stick → crafting_table → wooden_pickaxe, затем копать requested block
- если брёмна нет рядом — отказ с причиной «нет брёвен для крафта кирки» (не «нужен инструмент»)
- если инструмент может быть выкован из того, что есть (например, камень → stone_axe через крантер, или используются руками для softer blocks) — учитывать этот путь
- в ответе должен быть видно: crafted: wooden_pickaxe (да/нет), инструмент перед коллекцией был обеспечен, collected.cobblestone > 0
- обеспечение инструмента должно быть idempotent: если кирка уже есть — шаг пропускается, если нет — делается один раз

Вариант: новый вариант `collect_tool_alt_v2` — skill collect с обеспечением инструмента спереди и честным fallback. Подходит, когда требуется cobblestone/stone/coal, а кирки нет (после смерти, в новом мире или после долгого простоя). отличается от `collect_tool` (там шаг «инструмент» не надежно выполнялся, здесь — stricter check + fallback текст) и от `gather_list_alt_tool_v1` (там TypeError, а здесь — рабочая цепочка инструментов с проверкой каждого шага).

Простой до: 130+ мин за сутки (текущий случай, days.log shows growing idle); построено за сутки: 0. Сверка прошлых заявок: `collect_tool.md` — «помогло частично (обеспечивало инструмент один раз, но не на каждом вызове)»; этот новый вариант решает проблему гарантированного обеспечения на каждом вызове и обработки случая полного отсутствия материалов.

Как проверить: запуск collect с block="cobblestone" при пустой сумке и рядом брёвен → ok:true, в ответе crafted есть wooden_pickaxe, collected.cobblestone > 0; при отсутствии брёвен рядом — отказ с причиной про брёвна (не «нужен инструмент»); в brain/runner.log нет повторяющихся ошибок «нужен инструмент для cobblestone»; послеcolection в сумке растёт количество cobblestone; повторные запуски collect гарантированно обеспечивают инструмент перед каждым сбором.
