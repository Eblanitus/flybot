# collect_tool_alt_v3_alt: готово
Версия: collect_tool_alt_v3_alt (новый вариант collect с гарантированным обеспечением инструмента спереди)
Запуск: curl.exe -s "http://127.0.0.1:3200/go?name=collect_tool_alt_v3_alt&block=cobblestone&count=10"
Params: block — имя блока для сбора (cobblestone, stone, coal, spruce_log), по умолчанию cobblestone; count — количество, по умолчанию 1; items — альтернатива block/count в формате "block:count,..."; radius — радиус сбора, по умолчанию 48; deep — копать в глубину (true/false); style — стиль копки (auto и др.)
Что делает: гарантирует обеспечение деревянной кирки спереди НА КАЖДОМ вызове collect, требующем инструмент (cobblestone, stone, coal, руды, spruce_log). Idempotent: если кирка уже есть — шаг пропускается, но обеспечение повторяется каждый раз. Цепочка крафта: бревно → доски → палки → верстак → wooden_pickaxe. Если брёвнов рядом нет — честный отказ «нет брёвен для крафта кирки» (не «нужен инструмент»). После обеспечения инструмента сразу копает requested block без паuzz на проверку инструмента. Возвращает collected, crafted (включая wooden_pickaxe: 1 если скрафчена), pickaxeEnsured (true если обеспечена на этом вызове), sec.
Ограничения: требует доступных брёвен (spruce/oak/birch) в радиусе сбора для крафта кирки; не умеет крафтить каменную/железную кирку (только деревянную); тело collect должно уметь добывать указанный блок; не решает за мозг, куда идти — только собирает по параметрам. Обеспечивает инструмент гарантированно на каждом вызове, а не только при первом запуске gather_list.

Сравнение с collect_tool_alt_v3:
- v3: обеспечение инструмента гарантировано, но только при первом запуске gather_list в рамках постройки; повторные вызовы collect внутри одной постройки могут падать с «нужен инструмент»
- v3_alt: обеспечивает инструмент гарантированно НА КАЖДОМ вызове collect, idempotent: каждый вызов проверяет и обеспечивает инструмент с нуля, даже если предыдущий вызов уже обеспечивал его; stricter fallback «нет брёвен» вместо смешанных сообщений; сразу копает после обеспечения без пауз

Сравнение с collect_tool_alt_v4:
- v4: ensure_tool сохраняется в состоянии задачи до completion и не сбрасывается при переключении task'ов; gather_list блокирует build_blueprint до verified ресурсов в inventory
- v3_alt: обеспечение инструмента происходит прямо в collect, idempotent на каждом вызове, keine Persistenz im Task-State, но гарантировано на каждом вызове

Как проверить: запуск collect с block="cobblestone" при пустой сумке и рядом брёвен → ok:true, в ответе crafted есть wooden_pickaxe, collected.cobblestone > 0; повторный запуск collect без пересборки инвентаря → инструмент снова обеспечен (idempotent); при отсутствии брёвен рядом — отказ с причиной про брёвен (не "нужен инструмент"); в brain/runner.log нет повторяющихся ошибок "нужен инструмент для cobblestone" после внедрения варианта; после-colection в сумке растёт количество cobblestone; тот же эксперимент с spruce_log — гарантированно добыто > 0; повторные запуски collect гарантированно обеспечивают инструмент перед каждым сбором; build_blueprint перестает падать с "не хватает" при условии что инструмент обеспечен collect'ом спереди.
