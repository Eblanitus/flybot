# gather_list_alt_delta: готово
Версия: gather_list_v5 (новый вариант, взят за основу gather_list_v5)
Запуск: `curl.exe -s "http://127.0.0.1:3200/go?name=gather_list_v5&items=cobblestone:+46"` (смета без сбора: `&dry=1`)

Params: `items` — список `"имя:кол-во,…"` или объект `{имя:n}`; `max_sec` — потолок времени, 600; `dry=1` — только план (ничего не собирает); `+N` — дельта: добавить N к имеющемуся.

Что делает: понимает два смысла числа в items: по умолчанию «всего N» (достигнуть totals значения, как у gather_list), а также «ещё N» (добавить N к текущему имеютмуся, если items начинается с +). При «+N» цель = have + N; в ответе видно, что просили (+46), что лежало (55), что стало (101) и чего не добрали. Ответ ok:false только если ничего не собралось; если что-то добавилось — ok:true даже если не дошли до цели. Сбор по дельте не мешает постройке: не брает целью блоки самой постройки.

Успех: `{ok:true, have, missing, collected:{cobblestone:46}, crafted:{}, sec}`. Где collected показывает сколько реально добавилось (может быть меньше requested, если не хватает блоков). Провал: `{ok:false, error:'...', missing, collected:{}, sec}` — когда добавить нечего (рядом нет материала/время вышло), с указанием причины. dry=1: `{ok:true, dry:true, need, have, missing, raw, crafts, plan, renamed}` — показывает need 101, have 55, missing 46.

Ограничения: числа с + считаются как дельта (add), без + — как target (reach). Не собирает блоки, стоящие под мухой или которые она сама поставила (ownBlock). Если-material рядом нет — отказ с причиной, а не ok за 0.1 с. Вариант не блокирует старую поведение gather_list (без +).

(dry=1): `{ok:true, dry:true, need, have, missing, raw, crafts, plan, renamed}` — например need 101, have 55, missing 46.
