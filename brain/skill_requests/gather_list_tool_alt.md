# gather_list_tool_alt — от учителя ( альтернатива gather_list_tool: обеспечение инструмента с проверкой материалов цепочки)

Что не так: gather_list_tool обеспечивает инструмент (wooden_pickaxe) спереди перед collect, но если в цепочке крафта spruce_log→planks→sticks→table→wooden_pickaxe не хватает брёвен, он возвращает ошибку «нужен инструмент» вместо честного отказа «нет брёвен для крафта кирки». В результате collect для cobblestone/stone/coal падает, и bot простойт, а build_blueprint стоит с ошибкой «не хватает». Проблема возврается даже после supposedly-готовой gather_list_tool.done.md — сборы все еще падают «нужен инструмент» когда材料 для craft-цепочки нет.

Доказательства:
- signal skill:gather_list case 20261023-103755-55: «не добрал: cobblestone x1 (cobblestone: навык тела \"collect\" не удался: нужен инструмент для cobblestone: wooden_pickaxe / golden_pickaxe / stone_pickaxe; скрафтить не вышло — wooden_pickaxe: не хвата)» — самый свежийFail; ошибка «скрафтить не вышло — wooden_pickaxe: не хвата» означает craft-цепочка началась, но материалы закончились
- gather_list_tool.done.md заявление «готово» но случай 20261023-103755-55 случается снова — инструментообеспечение не покрывает случай когда материалов для craft-цепки (брёвна) нет в инвентаре
- day_report day 37: «построено 0 блоков, простой 18 мин (самый длинный 51 мин), warn: строительство за день не сдвинулся: 0 блоков построено»
- runner.log recurring patterns: gather_list ok:false + «не добрал: cobblestone» при отсутствии spruce_log для craft wooden_pickaxe

Кто решал: skill:gather_list — autopilot запросил сбор для постройки hut_west, gather_list вызвал collect без обеспечения инструмента и материалов цепочки

Версия: — (текущая gather_list_tool не проверяет доступность материалов для craft-цепочки перед стартом). Новый вариант: gather_list_tool_alt — перед обеспечением инструмента проверяет, есть ли в инвентаре/окрестях материалы для craft-цепки (брёвна для wooden_pickaxe). если нет — честный отказ «нет брёвен для крафта кирки» с указанием чего не хвата, а не «нужен инструмент». если есть — proceeds как обычно: craft→collect.

Что нужно (не код):
- gather_list_tool_alt должен проверять availability материалов для craft-цепочки каждого блока в items, требующего инструмент (cobblestone, stone, coal, и др.)
- для wooden_pickaxe: нужны spruce_log (или иныеLogs) → spruce_planks → stick → crafting_table → wooden_pickaxe
- если материалов для крафта нет — отказ с причиной «нет брёвен для крафта кирки (нужен spruce_log xN)», а не «нужен инструмент»
- если материалов достаточно — craft-цепочкой делает wooden_pickaxe, затем collect для requested blocks
- в ответе должен быть видно: crafted.wooden_pickaxe (если был крафт) или ошибка про отсутствие материалов (не «нужен инструмент»)
- сборы без инструмента (только доски/брёва, не требующие кирки) работают старой логикой без этого шага

Вариант: новый вариант `gather_list_tool_alt` — альтернатива gather_list_tool с проверкой материалов craft-цепки спереди. Подходит, когда требуются cobblestone/stone/coal для постройки, кирки нет, и材料 для крафта кирки (брёвна) могут отсутствовать (после смерти, в новом мире, после долгого простоя при строительстве). отличается отgather_list_tool (там нет проверки материалов цепочки, она возвращает «нужен инструмент» когда craft падает) и от обычного gather_list (тот вообще не обеспечивает инструмент).

Простой до: 0 мин за сутки (день 37, events.log #62 day_report); самый длинший 51 мин; построено за сутки: 0 блоков. Сверка прошлых заявок: gather_list_tool.done.md — «помогло: инструментообеспечение добавили», но проблема возвращается когда材料 для craft-цепочки нет; этот случай — новый вариант gather_list_tool_alt, так как gather_list_tool не решает случай absence материалов для craft-цепочки.

Как проверить: запуск gather_list_tool_alt с items="cobblestone:32" при пустой сумке и рядом spruce_log → ok:true, в ответе crafted есть wooden_pickaxe, collected.cobblestone > 0; при отсутствии spruce_log рядом → ok:false, error «нет брёвен для крафта кирки (нужен spruce_log)», а не «нужен инструмент»; в runner.log нет ошибок «нужен инструмент для cobblestone» при наличии брёвен; build_blueprint hut_west перестает падать с «не хватает» при условии что инструмент обеспечен или честно отказано; после сборки в сумке растёт количество cobblestone.
