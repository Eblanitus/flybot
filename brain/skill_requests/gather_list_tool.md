# gather_list_tool — от учителя (новый вариант: сбор с обеспечением инструмента)

Что не так: skill `gather_list` вызывает `collect` для добычи cobblestone, но `collect` падает с ошибкой «нужен инструмент для cobblestone: wooden_pickaxe», когда в инвентаре нет деревянной кирки. Навык не обеспечивает инструмент сам, из-за чего build_blueprint стоит, муха простойт, и в итоге она не может построить хиту.

Доказательства:
- signal `skill:gather_list` (case 20261023-012549-23): gather_list провал «не добрал: cobblestone x100 (cobblestone: навык тела 'collect' не удается: нужен инструмент для cobblestone: wooden_pickaxe)»
- events.log #1269-1270: task collectStarted/Done с ошибкой «нужен инструмент для cobblestone»
- runner.log #3526: run_end gather_list ok:false sec 313.1 error «не добрал: cobblestone x100»
- day_report day 9: «построено 0 блоков, простой 20 мин (самый длинный 136 мин), warn: строительство за день не сдвинулось: 0 блоков построено»
- runner.log #16-18: многократные провалы gather_list с той же причиной «не добрал: cobblestone»
- build_blueprint events.log #1209, #1265: «не хватает: cobblestone ×33, spruce_fence ×2» и «не хватает: cobblestone ×101, …»

Кто решил: skill:gather_list (код) → autopilot (задавал сбор для build_blueprint hut_west).

Версия: — (текущая версия gather_list вызывает collect без обеспечения инструмента). Новый вариант: `gather_list_tool` (такая же цель — собирать ресурсы для постройки, но с обеспечением инструмента спереди перед каждым сбором, отличие от обычного gather_list: там шага «инструмент» нет, а здесь он встроен спереди; отличие от gather_list_alt_tool/v1: там TypeError, а здесь — рабочая цепочка инструментов).

Что нужно (не код):
- gather_list (вариант gather_list_tool) должен проверять, нужен ли инструмент для каждого блока в items (cobblestone, stone, coal_ore и др.)
- если инструмента нет — gather_list должен сначала обеспечивать инструмент: spruce_log → spruce_planks → stick → crafting_table → wooden_pickaxe, и только потом вызывать collect для requested block
- если брёвен рядом нет или не хватает досок/палок — честный отказ с причиной «нет брёвен для крафта кирки», а не «нужен инструмент»
- в ответе должен быть видно, что инструмент был сделан (crafted: wooden_pickaxe) и сколько блоко собрано (collected.cobblestone)
- обеспечение инструмента не должно заканчиваться по причине «сначала нужен инструмент» — этот шаг встроен в сам gather_list, а не возвращается как ошибка
- если список можно выполнить без инструмента (только доски/брёвна, которые не нуждаются в кирке) — старая логика без инструмента работает

Вариант: новый вариант `gather_list_tool` — gather_list с обеспечением инструмента спереди. Подходит, когда требуются cobblestone (или иные блоки, требующие инструмент) для постройки, а кирки нет (после смерти, в новом мире или после долгого простоя). отличается от обычного gather_list (нет шага «инструмент», он встроен спереди) и от gather_list_alt_tool/v1 (там TypeError: targets is not iterable, а здесь — рабочая цепочка инструментов).

Простой до: 20 мин за сутки (текущий день 9), самый длинный 136 мин (день 9, day_report #1214, events.log #1269); построено за сутки: 0. Сверка прошлых заявок: gather_list.md — помогало частично (поправка имен items stone→cobblestone), но инструментообеспечение не было добавлено, поэтому проблема возвращается; этот случай — новый вариант, так как gather_list по-прежнему падает «нужен инструмент» при вызове для cobblestone.

Как проверить: запуск gather_list с items="cobblestone:32" при пустой сумке и рядом брёвен → ok:true, в ответе crafted есть wooden_pickaxe, collected.cobblestone > 0; при отсутствии брёвен рядом — отказ с причиной про бр�ена (не «нужен инструмент»); в brain/runner.log нет ошибок «нужен инструмент для cobblestone» после внедрения варианта; build_blueprint hut_west перестает падать с «не хватает» при условии что инструмент обеспечен; послеcolection в сумке растёт количество cobblestone.
