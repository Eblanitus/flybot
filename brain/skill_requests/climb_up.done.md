# climb_up: готово

Запуск: `curl.exe -s "http://127.0.0.1:3200/go?name=climb_up&x=-399&y=67&z=30&steps=40"`

Params:
- `x`, `z` — цель по горизонтали (необязательно; без них навык поднимается «куда твёрже»);
- `y` (или `target_y`) — **абсолютная** высота цели (ноги). `to_y=67` — это «+67 вверх», а не «до 67»;
- `to_y` — на сколько блоков вверх от текущей высоты;
- `ground=1` — цель по высоте = поверхность рядом с (x,z) из survey (перекрывает `y`). Если поверхность не видна — отказ с причиной о мире;
- `steps` — максимум ступеней (по умолчанию 40, каждый подъём = +1 к высоте);
- `item` — из чего ставить ступеньки (если не задан — сперва брёвна/доски/гранит, а земля/булыжник/камень придерживаются на столбы);
- `need` — явное число блоков на подъём (перекрывает смету);
- `min_ratio` — доля сметы, при которой ещё можно начинать (по умолчанию 0.6: часть блоков добудется по дороге, копя стену). `strict=0` — проверку запаса отключить;
- `max_sec` — ограничение времени (по умолчанию 240 с);
- `dry=1` — ничего не копать: смета по всей высоте подъёма (need/have/missing/plan).

Что делает: сначала считает материал — нужно ≈1.5 блока на уровень + 5 в запас (округляем до 5), сравнивает с числом ставимых блоков в кармане и, если не хватает, **не начинает**: `ok:false`, `error` вида «не хватает блоков: нужно ~60, есть 12 (не хватает 48) — сначала собери (collect cobblestone 48)», `missing:{blocks:48}` (та же строка идёт в журнал навыка :3200/log). Потом поднимается: копает `dig_at` 2 блока впереди-вверху, берёт уступ (или ставит ступеньку `place_at` с опорой), залезает `goto`; если лесенка не вышла — подъём на месте: `dig_at` над головой → `pillar_up height=1`. Кончились блоки в середине — отказ с цифрами: «блоки кончились: поднялась до y=38 из 67, осталось 29 уровней, нужно ~50 блоков (есть 0, не хватает 50)».
Возврат: `{ok, at:[x,y,z], dug, placed, steps, pillars, goalY, need, have, missing, why}` (+ `error` при провале, `notes` — причины отказов по сторонам, `by_type` — состав блоков в кармане). Успех — `ok:true` и `at` на целевой высоте; провал — `ok:false` с `error` и числами.

Что исправлено (по заявке учителя):
1. **Счёт материала перед подъёмом** — не хватает, значит не начинаем (`need`/`have`/`missing`, отказ с числами). Смета `dry=1` теперь тоже по всей высоте подъёма, а не по «открытым уровням над головой»; в плане пишется, сколько блоков нужно, сколько есть, какие типы в кармане и из чего идёт столб, а что — ступеньки.
2. **Отказ в середине — с цифрами** (высота, сколько осталось уровней, сколько блоков нужно) вместо «нечем ставить столб».
3. **Столб — только из блока, который берёт тело.** Уточнение к заявке: тело берёт для `pillar_up` не только землю/булыжник/камень, а весь `PLACE_ORDER` (`lib/skills/basic.js:267`: dirt, coarse_dirt, netherrack, tuff, andesite, diorite, granite, calcite, sandstone, cobblestone, cobbled_deepslate, stone, deepslate, blackstone, end_stone) — прошлый отказ «нечем ставить: нужны земля/булыжник/камень (granite)» означал не «гранит не берут», а «гранита в кармане уже нет». Поэтому: столб строится сперва из dirt/cobblestone/stone, гранит/андезит/брёвна/доски идут на ступеньки (`place_at`), и specials — только как последний запасной вариант столба (с записью в лог), когда земли/булыжника/камня нет вообще.
4. **Инвентарь перечитывается после каждой установки блока** (`spend`/`refreshInv` + свежий снимок в начале каждого шага) — больше нет «нет в инвентаре: granite» на уже поставленном блоке.
5. **`ground=1`**: поверхность у цели ищется двумя обследовами (широкий и высокий); если не видна — отказ с причиной о мире «поверхность у цели (x,z) не видна — задай y (абсолютная высота цели) или to_y», а не «нужна высота цели». Если `y`/`to_y` заданы — берётся он, в лог пишется, что поверхность не видна.
6. **Добыча рядом** (блоков нет совсем) — не больше одного раза на уровень, с понятной строкой в журнале навыка; если рядом нечего копать — отказ с числами.

Ограничения: подъём строго вверх на 1 блок (пройти «поверх» лестницей/тропой навык не умеет); на каждый подъём на месте нужен 1 столбовый блок, на ступеньку — 1 любой; `pillar_up` требует 2-3 свободных блока над головой (сначала `dig_at`); смета — оценка (1.5 на уровень), фактический расход бывает больше, если стены нет и каждый уровень требует «опора + ступенька»; в мире не проверено (инженер не управляет мухой) — проверка по заявке: с дна каньона (y≈30) вызвать `y=67` при 12 булыжниках → отказ сразу с числами («нужно ~60, есть 12») и без пустых `place_at`; после `collect cobblestone 60` подъём должен дойти до цели.
