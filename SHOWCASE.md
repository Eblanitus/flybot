# Витрина навыков (этап H)

Каждый бот выкладывает свои навыки со статистикой. Формат один для всех: наш (FlyBot_01, тело на :3199) и Ассасин (:3099, этап G)
отдают одно и то же. Учитель читает витрину соседа, видит, где у того лучше, и заказывает инженеру переделать под свою муху.
Только чтение: две GET-ручки, ничего не меняют и не запускают. Только 127.0.0.1.

## `GET /showcase`

```json
{
  "bot": "FlyBot_01", "version": "FlyBot 0.1", "format": 1, "updated": "2026-10-21T20:00:00.000Z",
  "skills": [
    { "name": "mine_vein", "kind": "learned", "about": "что делает, одной-двумя фразами",
      "params": { "ore": "iron | copper | coal …", "max": "сколько блоков, по умолчанию 16" },
      "stats": { "runs": 31, "ok": 17, "fail": 14, "lastErrors": ["…", "…"], "since": "2026-10-21T07:38:13.673Z" } }
  ]
}
```

| Поле | Смысл |
|---|---|
| `bot` | ник бота; `version` — версия бота, строка; `format` — версия этого формата (сейчас 1); `updated` — когда собрано (ISO UTC) |
| `skills[].name` | уникальное имя в пределах витрины. Варианты — `<семейство>/<имя>` (`melee/kite`), поведение — `behavior/<файл>` |
| `skills[].kind` | `body` — навык тела (встроенный, в коде бота); `learned` — выученный (написан инженером, запускается исполнителем); `behavior` — файл поведения (автопилот, рефлексы, пороги); `variant` — вариант действия (способ боя и т. п.) |
| `family` | только у `variant`: семейство (`melee`) |
| `about` | что делает; `null`, если описания нет |
| `params` | необязательно: объект `{имя: подсказка}` или строка — какие параметры принимает |
| `enabled` | необязательно, только `false`: навык отключён (например, три провала подряд) |
| `stats.runs / ok / fail` | запуски, успехи, провалы. `null` — такой статистики у бота нет; `0` — данные есть, но запусков не было |
| `stats.lastErrors` | до 3 последних разных причин провала (текст как есть, до 200 знаков), самая свежая последней; `[]` — провалов не было; `null` — не ведётся |
| `stats.since` | с какого момента (ISO UTC) считана статистика; `null`, если не знаем |
| `stats.avg` | необязательно, у `variant`: средняя оценка исхода 0..1 |

Статистику не выдумываем: чего бот не записывает, там `null`. Сравнивать навыки между ботами по `runs` и доле `ok/runs`;
мало запусков (меньше ~10) — не повод делать выводы.

Откуда берёт наш бот (`lib/showcase.js`): навыки тела — события `task_done`/`task_failed` в `data/events.log` (даты в этом журнале нет, поэтому `since: null`);
выученные — `brain/skills_stats.json` и `run_end` в `brain/runner.log`; варианты — `data/variants.json` (уровень «*», все обстановки вместе);
поведение — запусков нет, статистика `null`. Результат кэшируется на 1 минуту.

## `GET /showcase/code?name=<name>`

Исходный текст навыка: `{ "ok": true, "name", "kind", "family"?, "file", "size", "code" }`. Если имя неоднозначно, можно добавить `&kind=…`.
Ошибки: `400` плохое имя, `404` нет такого навыка, `413` файл больше 200 КБ, `403` файл вне разрешённых папок.

Защита: имя ищется среди навыков из `/showcase`, путь из присланного текста не собирается (`../`, абсолютные пути и чужие файлы невозможны);
отдаются только файлы внутри разрешённых папок: `lib/skills/`, `lib/variants/`, `behavior/`, `brain/learned/` (и `lib/commands.js` для навыка `follow`).
Данные игры (`data/`), заметки, ключи и конфиги не отдаются никогда.

## Для Ассасина (этап G)

Достаточно отдавать те же два адреса в том же виде. Допустимо оставить `null` там, где статистики нет, и не выкладывать то, чего нет
(например, `behavior`). Учитель при чтении соседа ничего не предполагает: нет эндпоинта, нет поля или `runs < 10` — вывода нет.
