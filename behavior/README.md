# behavior/ — поведение тела мухи

Поведение решает «как и когда»: автопилот, рефлексы, выбор способа ближнего боя, пороги.
Ядро (`bot.js`, `lib/`) — руки, глаза, законы игры, задачи, события, честность; его отсюда не меняют.

## Контракт (`index.js`)
```js
module.exports = {
  API: 1,                       // версия интерфейса ядра
  attach(api) { return { detach(reason) {} } },  // подключиться к боту
  selfTest: async () => {},     // самопроверка без бота; бросила — версия не включится
  chooseMelee(ctx, sit, opts),  // выбор способа ближнего боя (зовёт lib/skills/combat.js)
};
```
`api`: `ctx`, `bot`, `every(ms, fn, name, {always})`, `after(ms, fn, name)`, `on(emitter, event, fn, name)`,
`handle('player_attack' | 'mob_hurt', fn)`, `log(type, data)`. Таймеры и подписки снимает ядро само.
Модули ядра — только через `require('./core')('<имя модуля lib/>')` (работает и в сохранённых копиях версий).

## Проверка и включение
1. `node test/behavior.js` (и `node test/offline.js`) — `OK`.
2. `POST http://127.0.0.1:3199/behavior/reload` — ядро грузит, проверяет экспорт, гоняет `selfTest` (15 с).
   Не прошла — не включается, работает прежняя.
3. `GET http://127.0.0.1:3199/behavior` — активная версия, рабочая ли, история откатов.

Включённая версия, которая бросает исключения (20 за минуту), падает в `attach` или виснет (ожидание дольше 2 мин),
откатывается на последнюю рабочую. Рабочей версия становится, продержавшись 3 мин без сбоев.
Копии версий — `data/behavior_versions/<время-хеш>/`, список — `index.json`; события — `behavior` в `data/events.log`.
