## 1. Главный вывод

Это **не один проект, а два проекта в одной папке**:

1. **FlyBot 0.1 (архив, 21.10–31.10)** — Minecraft-бот на mineflayer, которым управляют четыре LLM-роли через локальное HTTP API: «мозг» ставит цели, «учитель» разбирает смерти, «инженер» пишет JS-навыки, «исполнитель» их запускает. Описан в `REBUILD.md`, `SKILLS.md`, `SHOWCASE.md`.
2. **Хардкор-стенд (активная разработка, 01.11–04.11)** — новый исследовательский проект: бот должен жить дольше и развиваться от жизни к жизни в хардкоре, перенося умения, а не координаты. Программа и этапы — `docs/goal_path.md`; код — `hardcore/`.

Поворот зафиксирован документально: `docs/improvement_plan.md:99` («Этап 4 "Мост" отменён хозяином 01.11: проект новый, FlyBot — архив»), `docs/goal_path.md:217-229` («Новый проект — в новой папке. FlyBot остаётся архивом; нужные части копируются»). Последние 20 коммитов — исключительно про стенд (1а, 1б, 1в).

**Но архив не заморожен**: `hardcore/fly.js` запускает те же `bot.js` и `brain/runner.js` с env-переопределениями (`DATA_DIR`, `RUNNER_URL`, `FLYBOT_NO_BRAIN=1`), то есть новое направление опирается на старое тело. При этом `brain/notes.md` до сих пор содержит цель «Цитадель над Бездной» с координатами базы `-393 67 36` — ровно то, что `docs/goal_path.md:130` прямо запрещает переносить. Это главное противоречие репозитория: план говорит «архив», код говорит «переиспользуем», а блокнот мозга живёт старой целью.

**Состояние на момент анализа**: рабочее дерево чистое (`git status` пуст), 107 коммитов (первый 21.10, последний `57c1e3c` 04.11), все 51 тест проходят (`npm test`, 3 м 35 с). Процессы `bot.js`, `runner.js`, `stand.js` и Java-сервер **не запущены** — система остановлена.

### 2.2 Ключевые контуры

- **Факты ≠ решения.** `lib/body_events.js` только фиксирует события мира; решения принимают `behavior/reflexes.js` и `behavior/autopilot.js`. Ядро (`lib/`) неизменяемо для мозга, поведение версионируется: `lib/behavior_host.js` перед включением грузит версию без кэша, валидирует экспорт, гоняет `selfTest()` с таймаутом 15 с, хранит 30 снимков в `data/behavior_versions/`, а откат делает только мозг через `POST /behavior/rollback`.
- **Основной цикл:** `GET /snapshot` → команда `/cmd` или `/do` → `TaskManager` (одна задача, FIFO до 5, `wait=1` ≤20 с) → навык → события `task_done/task_failed` → `GET /wait` (long-poll до 300 с) будит мозг.
- **Петля обучения:** смерть/почти-смерть → `lib/blackbox.js` (≈60 с кадров) → `lib/teacher_triggers.js` → учитель (вердикт: «информация была / не была / не повезло») → заявка в `brain/skill_requests/` → инженер пишет `brain/learned/<имя>_vN.js` → `brain/versions.js` → runner → статистика в `brain/skills_stats.json`.
- **Выбор без LLM:** `lib/variants.js` + 44 файла `lib/variants/<семейство>/` — UCB-подобный выбор способа (бой, побег, укрытие, подъём, копка, установка) по `data/variants.json`; `lib/experience.js` — таблица ситуаций; `lib/danger.js` — «время до смерти» по угрозам.
- **Хардкор-цикл:** `stand.js` создаёт `server.properties` (hardcore, large_biomes), поднимает Java, запускает мух, по смерти последней/archiving мира пересоздаёт его; карточки жизней в `lives.jsonl`, лента в `hardcore/data/timeline/index.html`.

### 2.3 Стек

Node.js CommonJS, **3 зависимости** (`mineflayer ^4.39`, `mineflayer-pathfinder ^2.4.5`, `vec3`), без TypeScript, линтера, CI и devDependencies. Тесты — собственный раннер `tools/run_tests.js` на встроенном `assert`: каждый `test/*.js` отдельным процессом, таймаут 5 мин. Оркестрация — 12 файлов `.cmd`/`.ps1` только под Windows, с жёстко зашитым `C:\Users\user\flybot` (`brain_guard.ps1`, `restart_brain.ps1`). LLM — бесплатные модели через `opencode` (`models_config.js`, `data/models.json`), с переключением на запасную после 3 ошибок провайдера за 2 ч. Ключи вне репозитория (`auth.json`, env).

## 4. Сильные стороны

1. **Честная архитектурная граница** «ядро = факты и руки / поведение = решения» (`REBUILD.md`, `behavior/core.js`) — редкая для самописных агентов дисциплина.
2. **Горячая замена поведения с проверками**: валидация экспорта + `selfTest()` + счётчики `faults/crashes/hangs` + событие `behavior_trouble`; сломанная версия не включается, откат — осознанное решение, а не автоматический галлюцинирующий фикс.
3. **Богатая офлайн-проверка**: 51 тест на поддельных ботах, без игрового сервера; тесты на версии навыков, откаты, зависания, витрину, PowerShell-скрипты. Это реально экономит игровые сутки.
4. **Наблюдаемость**: чёрный ящик, учёт ресурсов `ledger`, дневные отчёты, 14 вкладок аудита, витрина навыков со статистикой, атрибуция «кто отдал команду» (`lib/origin.js`) — данные для разбора причины, а не догадки.
5. **Честность игры**: зрение без рентгена (`lib/vision.js`), запрет `/`-команд мозгу, песочница `opencode.json` (deny на edit/bash/web), судья `lib/referee.js`.
6. **Устойчивость**: бесконечный реконнект с backoff 2→60 с, сторож входа, сторож зависших promises, атомарная запись `tmp+rename` в ключевых модулях, лимиты тел запросов и long-poll.
7. **Документированность решений**: каждое число порога в `behavior/thresholds.js` снабжено ссылкой на конкретную смерть, а планы improvement/goal_path содержат измеренные «ДО» и критерии готовности.

## 5. Риски и техдолг

### P0 — безопасность и ресурс

- **Сгенерированный код исполняется с полными правами Node.** `brain/worker.js:56,168` делает `require(file)`; `lintSource()` (`brain/runner.js:140-148`) лишь *предупреждает* про `child_process`/`process.exit`, `vm.Script` (`:153`) проверяет только синтаксис. 167 навыков + 160 снимков истории никем не ревьюируются. Песочница `opencode.engineer.json` ограничивает **запись**, но не **исполнение** уже записанного: навык может читать `auth.json`, env и сеть.
- **У всех локальных API нет аутентификации.** `:3199 /cmd`, `:3200 /run`, `:3300 /api/*`, `:3099`, `:3310+N`. Защита — `127.0.0.1`, `Host`/`Origin`/`Content-Type`, флаг `X-Observer`. Атрибуция «мозг или автопилот» строится на отсутствии `User-Agent` (`bot.js:151`) и подделывается одним заголовком. Любой локальный процесс может отдать команду телу или откатить поведение.
- **Неограниченный рост диска.** Ротация `tools/rotate_log.js` (20 МБ, 3 архива) вызывается только *перед стартом тела*; `events.log`, `deaths.log`, `guard.log`, `teacher-*.log`, `stand.log`, `lives.jsonl` пишутся только дозаписью. Живое свидетельство — 124 МБ один лог. `hardcore/archive/` = 2,26 ГБ: каждая жизнь копирует 167 JS навыков в `behavior_versions` ×10 ботов ×12 миров → 44 936 дублей JS.

### P1 — надёжность и поддерживаемость

- **God-object `ctx`**: ~50 динамических присваиваний `ctx.*` в `bot.js`/`lib`/skills, без схемы; порядок `attach()` в `bot.js:163-176` критичен (комментарий «ownblocks ДО ledger»).
- **Подавление ошибок**: 459 вхождений `catch (e) {}` в отслеживаемом JS; глобальные `uncaughtException`/`unhandledRejection` (`bot.js:369-370`) только пишут в консоль — процесс может стать «зомби». `stats.json` пишется напрямую каждые 10 с (`bot.js:138`), без `tmp+rename`; в `data/` есть осиротевший `teacher_queue.json.tmp46756` и `brain_guard.broken_*.ps1`.
- **Монолиты**: автопилот 2 083 строки с сотнями ручных очков и заплаток под конкретную базу; `behavior/thresholds.js` — ~150 магических чисел; `worldmem.js` смешивает хранение, HTTP и декоратор; `/snapshot` — вручную вложенная цепочка из 5 `decorate` (`bot.js:253`).
- **Перегруз контекста LLM**: `docs/0.2-prep.md:30` фиксирует «мозг читает на старте ~250 КБ»; `brain/core_requests.md` 147 КБ, `docs/goal_path.md` 123 КБ. Бесплатные модели для учителя не вытянули роль — `docs/goal_path.md:19`, «18% случаев сорвано лимитами» (`improvement_plan.md:35`).
- **Историческое качество обучения**: успешны 43% запусков выученных навыков, 122 навыка ни разу не запускались, 13 привязаны к координатам старой базы, из 64 уроков подтверждены 2 (`docs/goal_path.md:97-102`). `restore()` в `lib/core_requests.js` однажды стёр правки двух кодеров (`improvement_plan.md:38`).
- **Противоречие «без читов»**: `lib/referee.js` шлёт `/spreadplayers`, `bot.js:188` — `/gamemode survival`, хотя `docs/goal_path.md:136` прямо называет судью читом и запрещает переносить.
- **Мёртвый код**: `mcp/` — только `package.json` + lock + 3 658 файлов `node_modules`, сервера нет, `flybot-mcp` нигде не импортируется; `opencode.json:64-85` содержит лишь выключенные сторонние MCP. Три разных модуля «глаза» (`perception.js`, `eyes.js`/`tools/eyes.js`, `eyes_client.js`).
- **Хрупкие связи**: витрина навыков парсит исходники регулярками (`lib/showcase.js:103-125`); `SKILLS.md` и шапка `bot.js:6-23` отстали от кода (нет `/do`, `/memory*`, `/chat`, `/owner_msg`, `/showcase/code`); порт по умолчанию `3099` ≠ рабочему `3199`; порты и версия MC `26.1` размазаны по 10+ файлам.

### P2 — процесс разработки

## 6. Рекомендации

**С учётом того, что FlyBot официально архив, приоритеты такие:**

1. **Развести два проекта физически.** Новый проект — в новую папку/репозиторий, как предписано `docs/goal_path.md:217`. В FlyBot сделать тег `flybot-0.1-archive`, заморозить `brain/notes.md`, `SKILLS.md`, `REBUILD.md` и перестать коммитить `brain/learned/`, `skill_requests/`, `core_requests.md`. Сейчас план и код противоречат друг другу.
2. **Переносить по белому списку**, уже составленному в `docs/goal_path.md:113-124`: тело/снимок, `lib/skills/`, варианты со статистикой, `experience.js`, `danger.js`, `blackbox.js`, тесты. Не брать: автопилот, координатные чертежи, LLM-роли на бесплатных моделях, память мира, судью с `/spreadplayers`, счётчик «блоков».
3. **Сначала базовая линия, потом учитель.** Этап 1б ещё не закрыт: нужны 100 жизней (10 миров × 10 ботов) и сравнение «с памятью / без». Добавлять учителя (этап 2) до измеренной точки отсчёта — повторять ошибку FlyBot, где 64 урока дали 2 подтверждённых.
4. **Если текущий контур останется работать хотя бы для стенда** — три обязательных фикса: (а) токен/секрет на всех localhost-API; (б) изоляция выученных навыков (отдельный процесс с запретом `fs`/`net`/`child_process`, а не `require` в worker); (в) единая ротация всех логов + политика хранения `hardcore/archive` (не копировать дерево кода в каждую жизнь).
5. **Гигиена кода**: атомарная запись всех state-файлов, замена пустых `catch` на логирование, JSDoc/схема для `ctx`, разделение `autopilot.js`/`worldmem.js`/`audit/server.js`, корневой README с картой портов, CI под Windows с `npm test`.
6. **Гигиена репозитория**: вынести `hardcore/data/`, `hardcore/archive/`, `data/archive/` в `.gitignore`/внешнее хранилище (сейчас рабочая папка в ~240 раз больше `.git`), удалить `mcp/` или довести до рабочего сервера, архивировать 124-МБ лог.
