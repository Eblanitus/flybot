# Пул навыков мух (этап 2)

Принцип хозяина (04.11): не «дыра → навык», а широкий пул разных навыков на каждое дело. Муха с температурой сама их пробует,
общий счёт всех мух отсеивает плохие.

## Что здесь

| Файл | Что делает |
|---|---|
| `catalog.json` | 87 чужих навыков по 9 делам: wood 11, stone 10, furnace 9, food 11, farm 14, night 9, iron 12, combat 7, bed 4 |
| `voyager/t1..t3/`, `odyssey/` | чужой код как есть (124 файла: сами навыки и навыки, которые они зовут) |
| `shim.js` | переходник: чужой код думает, что у него mineflayer, а каждое действие уходит в тело мухи |
| `pick.js` | выбор с температурой и общая память `hardcore/data/pool_runs.jsonl` |
| `run.js` | дело по сумке, выбор навыка, запуск, запись итога |
| `gate.js` | цель рядом: навык, который ходит в поиске, предлагается только когда цель видна рядом (таблица `NEED`) |

Зовут пул выученные базы `brain/learned/day_routine_v7.js` и `night_mine_v7.js`. Автопилот вызывает их как обычно.
В выборе участвует и родной навык (`day_routine_v6`, `night_mine_v6`), на равных с чужими.

## Как муха выбирает

1. Дело по сумке. Днём: нет кирки → дерево; нет каменной → камень; голодна или еды меньше 4 → еда (70%) или поле (30%);
   нет печи или факелов → печь/свет; нет железной кирки или брони → железо; нет кровати → кровать; иначе случайное дело.
   Ночью: подземные навыки, а с мечом или луком в 30% случаев бой.
2. Навык дела. В 70% случаев берётся лучший по счёту (ok+1)/(runs+2) среди опытных (≥ 5 запусков) и родного.
   В 30% случаев берётся новичок, и первым идёт тот, кого ещё ни разу не пробовали.
3. Удача — навык не бросил ошибку и что-то сдвинулось: прибавилось в сумке, надета броня, муха поела, вспахала, посадила
   или накормила пару животных. Этим же правилом меряется и родной навык.
4. Итог пишется строкой в `pool_runs.jsonl`. Память одна на всех мух и все миры.

Чужому навыку даётся не больше 300 с. Родной работает со своими параметрами.

## Цель рядом (решение хозяина 05.11)

Навык, который ходит в поиске (зовёт `exploreUntil`), и разводящий навык предлагаются только тогда, когда цель видна рядом:
блоки — в окне 10 по ширине и 4 по высоте (survey, как видит муха), существа — не дальше 16 блоков (scan).
Таблица `NEED` в `gate.js` задаёт цель каждому такому навыку; навык, который не в таблице, — как был.
Если в сумке уже есть нужное (семена, шерсть), поиск не нужен, и навык предлагается без цели рядом.
Пещера — отдельная проверка в `run.js` (`caveInView`). Тест — `test/hardcore_pool_gate.js`: он же проверяет,
что каждый навык с поиском есть в таблице.

Поиск внутри чужого навыка тоже ограничен потолком: после 300 с (или `maxSec`) `exploreUntil` и поиск блоков и существ
бросают ошибку, а не возвращают пустой ответ. Раньше цикл «пока не нашёл» в пустом мире мог крутиться без конца.

## Переходник: что честно, что нет

- Мир чужой навык видит только глазами мухи. Сумка и позиция берутся из снимка тела, блоки из `survey` (радиус 9, ±4 по высоте;
  тело отдаёт не больше 4096 блоков), дальние руды и брёвна из `eyes.blocks`, существа из `scan`. Сквозь стены не видно,
  поэтому навыки, которым нужно «5 руд в 32 м», будут проваливаться чаще, чем у Voyager.
- Зрелость посевов не видна. Поэтому `bot.dig` по посеву уходит в `harvest` тела, а тот берёт только спелое.
- `bot.chat` пишется в журнал навыка. В чат сервера ничего не уходит, команд `/` в чужом коде нет (это проверяет тест).
- Соответствие действий: `mineBlock → collect`, `craftItem → craft` (рецепт ×N переводится в предметы), `smeltItem → smelt`,
  `killMob → hunt` для животных и `fight` для мобов, `placeItem → place_at`, `exploreUntil → explore` (вниз — `descend`),
  `bot.dig → dig_at`, `bot.equip → equip_item`, `bot.consume → eat`, `bot.fish → fish`, `activateBlock` с мотыгой → `till`,
  `placeBlock` с семенами → `plant`, `useOn` → `shear`, `breed` или ведро.
- Старые имена блоков (1.19) переводятся: фильтр `grass` находит нынешнюю `short_grass`.

## Проверка

`node test/hardcore_pool.js` прогоняет все 87 навыков на поддельном теле. Там проверяется, что у переходника нет дыр,
что выбор идёт 70/30, что дело определяется по сумке и что строки пишутся в общую память.
Вне стенда (переменной `HC_POOL_RUNS` нет) `day_routine_v7` и `night_mine_v7` просто зовут v6. Выключить пул на стенде
можно ключом `"pool": false` в `hardcore/config.json`.
